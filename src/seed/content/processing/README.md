# Обработка стекла — сид страниц услуг

Одна услуга — один файл: `kromka.ts`, `otverstiya-i-vyrezy.ts`, `facet.ts`, `matirovanie.ts`,
`pechat.ts`, `plenki.ts`. Хаб — `hub.ts`. Общее — `shared.ts` (`LINKS`, `tableBlock`), типы —
`types.ts`, список услуг в порядке хаба — `index.ts` (его не трогать). Слайс
`src/seed/slices/processing.ts` превращает записи в документы `processing-services`.

**Эталон — `facet.ts`** (макет Paper `2560_service_facet`). Все шесть услуг переведены на секции
макетов `2560_service_<name>` (`copy.source: "paper"`).

Схема заморожена: новых полей нет, каждая секция макета — существующее поле или блок.

Порядок секций задаёт шаблон (`src/components/templates/processing-template.tsx`), а не порядок
в `layout`: specs → блоки `layout` по порядку → плашки → «Что важно знать» и FAQ (если есть) →
«Другая обработка» → how-to-order. Внутри `layout` порядок сохраняется (about, калькулятор,
use-cases…). Блоки `twoColumns` можно ставить в конец `layout` — они всегда уходят в how-to-order.

### Правила по секциям

- **hero.** `introMd` — лид макета. Термины (галочки) берутся из глобала «Условия», в сид не
  писать. `image` — фото услуги (`src/seed/media/processing/<slug>.webp`, 16:9, 1920 px, предмет
  справа, левые ~45 % спокойные под заголовок), оно же фото карточек.
- **specs.** Обычно 4 плитки, у последней `accent: true` (светло-бирюзовая). `value` короткий
  (до ~10 символов: «5–40 мм», «Ø 4–130 мм», «от R10»). `label` — 1–4 слова, выводится КАПСОМ.
- **about.** `richText` обязательно с `heading` (H2), иначе блок рисуется обычным текстом сайта.
  Абзацы — 18 px, маркированный список `- …` — с бирюзовыми точками. `figure.caption` — подпись
  КАПСОМ над схемой («Сечение края с фацетом»). Без `figure` текст идёт одной колонкой.
  Вместо схемы может быть фото (`photos/<name>.webp`, 4:3, `kind: "photo"`): оно заполняет панель
  в рамке 4:3 со скруглением, без увеличения на телефоне (так у «Матирования»).
  Вместо схемы панель может быть таблицей сравнения — блок `table` сразу за `richText` (шаблон
  умеет, сид услуг пока нет; формат — `src/seed/content/glass-types/README.md`, «about»).
- **Схемы (`figure.image`).** Медиатека не принимает SVG (XSS), поэтому: исходник
  `src/seed/media/processing/diagrams/<slug>.svg` (цвета только из токенов, шрифт
  `Rubik, system-ui, sans-serif`, `<title>`/`<desc>` по-русски) и растр
  `diagrams/<slug>.webp` — экспорт узла SVG из Paper в WebP **2x** (Rubik «запечён»). В сид идёт
  WebP: `{ file: "diagrams/<slug>.webp", kind: "scheme", alt: "Схема …: что на ней показано" }`.
  `alt` описывает схему целиком (размеры, подписи), это единственный текст схемы для скринридера.
  Медиа ищется по пути файла (`sourceUrl`). Файл, перезаписанный картинкой других размеров,
  заменяет загрузку при следующем сиде (если редактор не загрузил в админке свой файл); при тех же
  размерах — новое имя файла (`<slug>-v2.webp`).
- **use-cases.** `columns: 3` для 3/6 карточек, `columns: 4` для 4. Номера 01, 02… ставит вёрстка.
  `image` у карточки — фоновое фото (`cards/<name>-<n>.webp`, 4:3, 1200 px, `alt` по-русски):
  карточка как на хабе конструкций (фото, светлая дымка снизу, текст внизу, номер на белой
  плашке). У всех карточек услуг фото есть (тест проверяет); без фото — белые карточки.
  `href` у карточки необязателен (вся карточка — ссылка, только внутренние пути `/…/`).
- **callouts.** Обычно одна плашка `tone: "warning"`. Кнопка справа — **последний абзац из одной
  ссылки**: `→ [Обработка кромки](${LINKS.edge})`. В тексте плашки эта ссылка не повторяется.
  Жирный — `**…**`.
- **related.** Без `related` показываются первые три другие услуги по `order` (для «Фацета» это
  Кромка, Отверстия, Матирование — как в макете). Если в макете другие — укажите
  `related: ["matirovanie", "pechat", "plenki"]` (ровно три, без текущей; тест проверяет).
  Подписи карточек — `cardTitle` и `keyLimit` тех услуг, их не дублировать.
- **how-to-order.** Первая панель — `howToSpecifyMd`. Первая строка `## Заголовок` заменяет
  заголовок по умолчанию «Как указать в чертеже». Первый абзац — лид (24 px), `### Подзаголовок:`,
  списки `1.`/`-`, строка `> …` — белая карточка с иконкой документа внизу панели. Следующие
  панели — колонки блока `twoColumns` (`left`, необязательный `right`) в том же формате.
  Две панели (как у «Фацета») — `howToSpecifyMd` + `twoColumns` только с `left`. Три панели
  (как у «Отверстий») — `howToSpecifyMd` + `twoColumns` с `left` и `right`. Таблица внутри
  панели — markdown-таблица в `md` (редактор поддерживает таблицы): рисуется белой карточкой панели
  (подписи столбцов КАПСОМ, значения справа жирным), на телефоне — та же таблица, не карточки.

### Тексты

- `copy: { source: "paper", mockup: "2560_service_<name>", pendingApproval: [...] }` — тексты
  из макета. Все утверждения с пометкой «[уточнить]» переносятся **без пометки**, а дословно
  (как в коде) перечисляются в `pendingApproval` и в
  `docs/inex/drafts/service-pages-paper-drafts.md`, раздел «Тексты на согласовании (перенесены
  в код 2026-11-08)», подраздел услуги. Тест сверяет: каждая строка есть в тексте записи и в
  этом документе, а «[уточнить]» в записи нет.
- Стоп-слова ТЗ §11 (+ уточнение 08.11) проверяет тест: нет «собственного производства»,
  «монтажа под ключ», стеклопакетов, HST и т. п.
- SEO (`seo.h1/title/description`) равны строке `docs/inex/17-meta.md`. Если новые факты
  противоречат title/description — правьте обе стороны (тест сравнивает).
- `keyLimit` — строка под названием на карточках хаба и «Другой обработки»; берите из макета
  (у «Фацета»: «На зеркалах и стекле, ширина 5–40 мм»).
- Плейсхолдеры `{условия}` и т. п. остаются в тексте и подставляются при рендере.

### Чего не делать

- Не менять `index.ts`, `types.ts`, `shared.ts`, слайс и шаблон из задачи одной услуги — это
  общие файлы. Нужно новое поле записи — к координатору.
- Не класть настоящие таблицы в `specs`: таблицы — блоки `table` в `layout` (`tableBlock({...})`).
- Не использовать блок `stats` для specs (в нём нет подписи КАПСОМ).
