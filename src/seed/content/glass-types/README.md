# Виды стекла — сид страниц

Один вид — один файл: `matovoe.ts`, `tonirovannoe.ts`, `okrashennoe.ts`, `osvetlennoe.ts`,
`dlya-mebeli.ts`, `riflenoe.ts`, `mollirovannoe.ts`, `tripleks.ts`. Общее — `shared.ts`
(`GLASS_TYPE_LINKS`, `link()`, `TEMPERED_LIMITS`, `EMPTY_HEADER`), типы — `types.ts`, список в
порядке хаба — `index.ts` (его не трогать). Слайс `src/seed/slices/glass-types.ts` превращает
записи в документы `glass-types`, шаблон — `src/components/templates/glass-type-template.tsx`
(секции — компоненты `src/components/processing/` и `src/components/glass-types/`).

**Эталон — `matovoe.ts`** (макет Paper `2560_glass_matovoe`, файл Scratchpad). Остальные семь
видов (2026-11-09) переведены на тот же дизайн по образцу «Матового» (`copy.source: "paper"`,
своих артбордов пока нет) и рисуются тем же шаблоном: секции, для которых у вида нет данных,
просто не выводятся. Перевод вида на макет `2560_glass_<slug>` —
правка только его файла `<slug>.ts` (+ раздел в документе согласования, + при необходимости
медиа в `src/seed/media/glass-types/`).

Схема заморожена: новых полей нет, каждая секция макета — существующее поле или блок.

## Секция макета → поле записи → что хранится в CMS

| 8   | faq           | `faq[]`                                                          | `faq[]` (+ FAQPage JSON-LD)                                                                             | `service-faq.tsx`                      |

Порядок секций задаёт шаблон, а не порядок в `layout`: hero → фото (`heroPhotos`) → specs →
[варианты, если в `layout` нет about] → прочие `tables[]` (legacy) → блоки `layout` по порядку
(about, **варианты сразу после первого about**, use-cases, прочие блоки сайта) → `applications`
(legacy, нумерованные карточки «Где применяют») → «Что важно знать» → образцы → объекты
(`showObjects`) → FAQ → «Другие виды стекла» (+ список прочих `relatedLinks`) → how-to-order.
Блоки `twoColumns` можно ставить в конец `layout` — они всегда уходят в how-to-order. Секции
«Условия» и финальных кнопок нет: их несёт первый экран.

### Правила по секциям

- **hero.** `intro` — лид макета (одна-две фразы, без `{условия}`: условия — галочки hero).
  `heroImage` — фото вида: `{ file: "<slug>.webp", alt, temporary: true }`, файл в
  `src/seed/media/glass-types/`. `temporary` — «Временное изображение» (фильтр в медиатеке),
  пока нет фото заказчика. **Без `heroImage`** справа в hero рисуется светлая заглушка `.ig-ph`
  «фото готовится» (только ≥1101 px); как только в админке выбрано изображение в поле
  «Изображение» вкладки «Первый экран», оно встаёт фоном hero. Сид пишет `heroImage` только если
  оно задано в файле, поэтому `--force` не стирает фото, загруженное в админке.
- **specs.** Обычно 4 плитки, у последней `accent: true`. `value` короткий (до ~10 символов:
  «4–12 мм», «20–70 %», «Любой»), `label` — 1–3 слова (выводится КАПСОМ). Хранится первой
  таблицей `tables[]`; прочие таблицы `tables[]` выводятся старой секцией таблицы сайта.
- **about.** `richText` обязательно с `heading` (H2). Абзацы — 18 px, список `- …` — с
  бирюзовыми точками. Правая панель — **либо** `table` (сравнение), **либо** `figure` (схема):
  - `table: { caption, columns, rows, highlightColumn? }`. `columns[0]` — пустой угол
    (`EMPTY_HEADER`), остальные — заголовки столбцов (КАПСОМ, коротко: «Сатинированное»).
    Каждая строка: подпись строки + по значению на столбец (длина = `columns.length`, тест
    проверяет). `highlightColumn` (с 1) красит заголовок столбца в бренд. В ячейках допустимы
    `**жирный**` и `[ссылка](/путь/)`. На телефоне каждая строка — группа «подпись → столбец:
    значение».
  - `figure: { image, caption }` — схема как на услугах (см. `src/seed/content/processing/README.md`,
    «Схемы»): исходник SVG + WebP 2x в `src/seed/media/glass-types/diagrams/`, `kind: "scheme"`,
    `alt` описывает схему целиком.
  - Таблицы из старого `tables[]` (teksty) переносите в about-панель, если в макете они справа
    от текста; если в макете таблица на всю ширину — `layout: { kind: "table", table }`.
- **варианты** (тонированное — цвета, рифлёное — узоры) остаются в полях `variants*` и
  рисуются отдельной секцией сразу после первого about (H2 = `variantsHeading`). Если в макете
  цвета показаны иначе (плитки, строка образцов) — сообщите координатору, не придумывайте поле.
  Цветные `variants` (`swatchKind: "color"`) также дают кружки на карточке вида в «Других видах
  стекла» (до 5).
- **use-cases.** `columns: 3` для 3/6 карточек, `4` для 4. Номера ставит вёрстка. `href`
  необязателен (вся карточка — ссылка; только внутренние пути `/…/`). Ссылки старой строки
  `relatedLinks`/`applications` переносите на подходящие карточки, а не теряйте.
- **callout.** Строки — `importantItems` (`lead` с точкой на конце + `text`), кнопка —
  `importantButton` (одна ссылка из `GLASS_TYPE_LINKS`). Заголовок всегда «Что важно знать до
  заказа».
- **samples.** Только флаг `showSamples`; текст общий для всех видов (глобал «Фрагменты»,
  ключ `samples`), в файл вида не писать.
- **faq.** Первый ответ открыт. FAQ есть у всех восьми видов; тест «gives every glass type its
  own FAQ» перечисляет виды и число вопросов — поменяли FAQ, поправьте ожидание в тесте (и
  `faq` в `e2e/glass-types.spec.ts`).
- **related.** `related: ["…", "…", "…"]` — ровно три других слага в порядке макета. Без него —
  три следующих вида по `order` (по кругу). Текст карточки — `card.text` того вида (первая буква
  заглавная), его же видит хаб `/zakalennoe-steklo/`. Если макет даёт другой текст карточки, меняйте `card.text` в файле
  **того** вида (для `copy.source: "teksty"` тест сверяет `card.text` с teksty/02).
- **how-to-order.** Один блок `twoColumns`: `left` «Как заказать», `right` «Как считается цена».
  Первый абзац — лид (24 px), `### Подзаголовок:`, списки `1.`/`-`, строка `> …` — белая
  карточка с иконкой документа внизу панели.
- **legacy-поля** (`tables`, `applications`, `relatedLinks`, `layout` с `callout`/`richText` без
  панели, `heroPhotoCaptions`) продолжают работать, но в новом дизайне их заменяют секции выше.
  Ничего не удаляйте молча: перенесите данные в новую секцию или оставьте как есть.

### Тексты

- `copy: { source: "paper", mockup: "2560_glass_<slug>", pendingApproval: [...] }` — тексты из
  макета. Все утверждения с пометкой «[уточнить]» переносятся **без пометки**, а дословно (как в
  коде) перечисляются в `pendingApproval` и в `docs/inex/drafts/service-pages-paper-drafts.md`,
  раздел «Виды стекла — тексты на согласовании (2026-11-09)», подраздел вида (по образцу
  «Матового»; там же — что изменилось по сравнению с teksty). Тест сверяет: каждая строка есть в
  тексте записи и в документе, слова «уточнить» в записи нет.
- `copy: { source: "teksty" }` — дословно из `source` (тест сверяет построчно). При переводе на
  макет смените на `paper` — проверка teksty для вида отключится.
- SEO (`seo.h1/title/description`) равны строке `docs/inex/17-meta.md`. Если новые факты
  противоречат title/description — правьте обе стороны (тест сравнивает).
- Стоп-слова ТЗ §11 (+ уточнение 08.11) проверяет тест: нет «собственного производства»,
  «монтажа под ключ», стеклопакетов, HST, «бронированного» и т. п.; на страницах видов стекла
  нет слова «фацет».
- Ссылки — только внутренние, строчные, со слешем на конце (`/obrabotka-stekla/matirovanie/`).
- Плейсхолдеры `{условия}` и т. п. допустимы и подставляются при рендере.

### Особенности видов

- **Тонированное** — `variants` (бронза, графит, серое; `swatchColor` — приблизительные тона до
  фото образцов) рисуются секцией «Цвета» после about и кружками на карточке в «Других видах».
  FAQ (3) и `importantItems` есть. Плитки specs по макету.
- **Триплекс** — живёт по адресу `/tripleks/` (`urlBase: "root"`, свой маршрут), квиз
  `type: "triplex"`, `showSamples: false`, `showInHub: false`, крошки «Главная › Триплекс».
  Таблица «Схемы» (6 строк, ссылка «Проектирование») проверяется e2e
  (`[data-glass-table="schemes"]`): если переносите её в about-панель или в `layout`, обновите
  тест «триплекс: schemes table». `limits.notes` — сырое стекло до 3500 × 2500 мм.
  `card.text` — строка карточки триплекса из макета `2560_glass_matovoe` («При ударе осколки
  остаются на плёнке. По ГОСТ 30826-2014»).
- **Осветлённое** — `heroPhotoCaptions` (пара фото торцов под hero) и таблица с 4 подсвеченными
  ячейками (`positive`; e2e и тест это проверяют).
- **Рифлёное** — 5 узоров (`swatchKind: "pattern"`, `patternKey`), интерактивный выбор; ключи
  проверяет тест.
- **Крашеное** — таблица параметров стала плитками specs, сравнение «Лакобель и эмалит: не
  путайте» — таблица about-панели (e2e «крашеное: spec tiles and «Лакобель и эмалит»…»).
- **Для мебели** — строка «Полированная кромка, «карандаш»…» — одобренная терминология кромок
  (`EDGE_TERMINOLOGY_APPROVED_STRINGS`), должна остаться в тексте дословно.

### Что выяснилось при переносе

- `copy.mockup` всегда `2560_glass_<slug>`, даже если своего артборда ещё нет (вид сделан по
  образцу «Матового») — тест слайса требует это имя.
- Прочие таблицы `tables[]` (кроме первой, specs) выводятся **до** about, сразу после specs
  (и вариантов без about), а не на месте в `layout`. Таблица, которая по смыслу идёт после
  текста, — в about-панель или `layout: { kind: "table" }`.
- В таблице about-панели нет подсветки ячеек (`positive`): только `highlightColumn` и
  `**жирный**`. Ячейки с `positive` (осветлённое) остаются в `tables[]`.

### Чего не делать

- Не менять `index.ts`, `types.ts`, `shared.ts`, слайс и шаблон из задачи одного вида — это
  общие файлы. Нужно новое поле или секция — к координатору.
- Не класть настоящие таблицы в `specs`.
- Не коммитить `src/payload-types.ts`, если он перегенерировался при сиде.
