### 2. Изображения

Проверить и исправить во всех местах использования картинок (`grep -rn "next/image\|<img\|background-image\|url(" src`):
- Используется `next/image` с относительным `src` медиа; никаких внешних доменов. Для размеров из Payload использовать подходящий `sizes` из коллекции (`media.sizes`) через `url` нужной ширины либо оставлять оптимизатор Next — не смешивать оба способа на одной картинке.
- У каждого `<Image>` корректный атрибут **`sizes`** по реальной сетке сайта (пример для карточки в сетке 4→2→1 колонки: `(min-width:1366px) 25vw, (min-width:601px) 50vw, 100vw`; hero на всю ширину: `100vw`; галерея объекта — по раскладке). Без `sizes` картинка с `fill` скачивается в завышенном размере — недопустимо.
- **Hero / LCP-элемент**: ровно одно изображение на страницу получает приоритет — в Next 16 используй `preload` (если проп поддерживается актуальной версией; `priority` объявлен устаревшим) либо `fetchPriority="high"` + `loading="eager"`; для остальных — `loading="lazy"` (дефолт). Всё ниже первого экрана — lazy, включая карточки каталога, галереи, превью в подвале. Определить LCP-элемент каждого шаблона по Lighthouse (hero-картинка или H1-текст) — при текстовом LCP не добавлять лишний preload.
- Фоны секций, заданные CSS `background-image`, не используются как LCP; если hero реализован фоном — перевести на `<Image fill>` с тем же видом (проверить визуальную идентичность скриншотом 375/1366/1920).
- Aspect ratio: у каждой картинки заданы `width/height` или контейнер с `aspect-ratio` — чтобы не было CLS.
- Конфигурация `images`: `formats: ['image/avif','image/webp']`; `deviceSizes: [375, 640, 828, 1080, 1366, 1536, 1920]`; `imageSizes: [64, 128, 256, 384]`; `qualities: [60, 75]` (качество 75 по умолчанию, 60 для крупных фоновых hero — через проп `quality={60}`; проверь, что значение входит в `qualities`, иначе Next 16 вернёт ошибку); `minimumCacheTTL`: 14 дней (`1209600`) — имена файлов медиа при замене получают новое имя, риск устаревания минимален; зафиксируй решение в отчёте.
- AVIF-кодирование на первом запросе тяжёлое: при необходимости задать `SHARP_CONCURRENCY`/ограничение, оценить время первого запроса картинки на целевом VDS (в отчёте); при проблемах — отдавать WebP первым (`formats: ['image/webp']`) и объяснить компромисс.
- Тяжёлые оригиналы: если `media` содержит файлы > 1 МБ, проверить, что оптимизатор получает их без падения (лимиты памяти `sharp`); исходные placeholder-WebP ≤ 2 МБ.
- Иконки — только Lucide (SVG-компоненты, tree-shaken); логотип — SVG; никаких иконочных PNG.

### 3. Шрифты

- Файлы `src/app/fonts/*.woff2`: проверить subset (latin + cyrillic + базовая пунктуация, `№`, `₽`, `×`, `−`, неразрывный пробел `U+00A0`, кавычки «», тире); размер каждого начертания ≤ 30 КБ (Rubik cyrillic woff2 обычно ≈ 20–25 КБ); суммарно для 5 начертаний ≤ 130 КБ. Если больше — пересобрать subset (`pyftsubset --flavor=woff2 --unicodes=U+0020-007E,U+00A0-00FF,U+0400-04FF,U+2010-2015,U+2018-201E,U+2022,U+2026,U+2116,U+20BD,U+00D7,U+2212`).
- `display: 'swap'` + `adjustFontFallback` (в `next/font/local` задаётся `adjustFontFallback: 'Arial'`) и системный fallback, подобранный по метрикам Rubik, чтобы замена шрифта не вызывала сдвиг.
- Preload: ограничить предзагрузку критичными начертаниями. Если `next/font/local` с одним семейством предзагружает все пять файлов — разделить: основной набор (400, 500, 600) с `preload: true`, редкие (300, 700 — используются в крупных заголовках?) определить по факту использования `font-light`/`font-bold` и либо оставить без preload (`preload: false` через отдельный `localFont`), либо убрать неиспользуемое. Решение обосновать по числу байт критического пути.
- Проверить отсутствие запроса к Google Fonts и любым сторонним шрифтам (Network).

### 4. JS-бюджет ≤ 150 КБ gzip на маршрут

Типовые меры, применять по результатам анализа:
- Серверные компоненты по умолчанию; `'use client'` — только в листьях (кнопки с обработчиками, формы, баннер, аккордеон при необходимости). Не импортировать клиентские барреловые файлы в серверные страницы (`@/components/ig` index с `use client`-модулями тянет всё).
- `next/dynamic` (с `ssr: false` только там, где допустимо без деградации SEO/первого экрана) для: квиза (на страницах, где он не основной — не грузить до открытия; на `/raschet-stoimosti/` грузить сразу), калькулятора отверстий и веса (грузятся на своих страницах), лайтбокса (по клику), `drawer` фильтров объектов, мобильного меню (по клику), мега-меню (hover/focus, но разметка для SEO уже в HTML), Яндекс.Карты (только по клику), cookie-баннера (после гидратации, может быть lazy).
- Radix-компоненты (Dialog/Select/Popover) импортируются только там, где нужны; проверить дубли версий в lock-файле.
- `lucide-react`: импорт именованный (`import { Phone } from 'lucide-react'`), `experimental.optimizePackageImports: ['lucide-react']`.
- `zod` на клиенте — только схемы форм/квиза (общий домен-код делит схемы с сервером; не тянуть в клиент серверные схемы и Payload-типы). Проверить размер zod в клиентском бандле; при необходимости `zod/mini` или `zod` v4 tree-shaking.
- Метрика и любые сторонние скрипты: загрузка через `next/script` со стратегией `lazyOnload`/по событию согласия; не блокируют INP; проверить отсутствие загрузки до согласия.
- Payload/Lexical/React Email не должны попадать в клиент: проверить анализатором; добавить `import 'server-only'` в серверные модули (`src/lib/cms/*`, `src/lib/leads/*`, `src/lib/uploads/*`, `src/emails/*`).
- Polyfills: `browserslist` современный (последние 2 версии evergreen + iOS ≥ 15) — Next 16 по умолчанию; не добавлять лишних полифилов.

### 5. CLS < 0.1

Проверить на мобильном (375) и десктопе в Lighthouse и через `PerformanceObserver({ type: 'layout-shift' })` в `e2e/perf-budget.spec.ts` (суммарный CLS от навигации до `load` + 3 с; исключить сдвиги после ввода пользователя):
- Картинки и видео — зарезервированные размеры (см. выше).
- Шапка: сжатие при прокрутке (sticky 56–64 px) НЕ меняет высоту потока (используется `position: sticky/fixed` + спейсер зафиксированной высоты); смена высоты строк при ресайзе не вызывает сдвиг.
- Cookie-баннер и sticky-CTA — `position: fixed`, не сдвигают контент; баннер не появляется «поверх с перетяжкой» после гидратации (рендерится в зарезервированном месте/как fixed, состояние из `localStorage` читается без мигания — скрыт по умолчанию через CSS-класс до проверки, но не создаёт сдвиг).
- Шрифты — см. fallback metrics.
- Таблицы цен/карточки с динамическим форматированием: значения форматируются на сервере (не пересчитываются на клиенте после гидратации, иначе мигание/сдвиг).
- Блоки, подгружаемые `dynamic`, получают skeleton/min-height такой же высоты, как итоговый компонент.
- Акционная плашка шапки (`promo` активна): место под неё зарезервировано сервером (рендерится в HTML, не добавляется клиентским кодом).

### 6. INP < 200 мс

- Тяжёлые обработчики (ввод в квизе, калькуляторы, фильтры объектов): без синхронных вычислений > 50 мс; дебаунс поиска 200 мс; `startTransition` для тяжёлых обновлений состояния (фильтры, поиск); `useDeferredValue` для списков.
- Формы: валидация на blur/submit, не на каждый символ для сложных схем.
- Лайтбокс/мобильное меню: открытие не вызывает синхронную загрузку больших ресурсов (предзагрузка по hover/idle).
- Отсутствие `scroll`/`resize` слушателей без `passive`/throttle (sticky-шапка — `IntersectionObserver` или `requestAnimationFrame`).
- Сторонние скрипты не блокируют основной поток (см. п.4). Измерение: Lighthouse TBT как прокси (цель ≤ 200 мс на мобильном профиле) + ручной замер INP в Chrome DevTools Performance на типовых взаимодействиях (клик по «Рассчитать стоимость» → модалка; переключение шага квиза; ввод в калькуляторе; открытие мега-меню).

### 7. Кэширование и заголовки (проверка)

- Статика `/_next/static/*` — `Cache-Control: public, max-age=31536000, immutable` (по умолчанию Next); оптимизированные изображения — `minimumCacheTTL`; HTML ISR — не `no-store` (проверить заголовки страниц: `s-maxage` + `stale-while-revalidate`); страницы `/zakaz/*` и приватные загрузки — `private, no-store` (не ломать).
- Подтвердить сжатие ответов HTML/JS/CSS (gzip/br). Traefik в Dokploy может добавлять brotli; на уровне приложения — gzip.
