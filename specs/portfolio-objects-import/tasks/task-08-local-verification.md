## Technical Details

### 1. Final covers (full run, moved here from task 06)

Needs the user's model decision from the pilot. Run over all manifest objects (content cover first, else `coverKey`):
`pnpm tsx --env-file=.env scripts/import-inex/upscale-covers.ts --model=<approved>` (`--dry-run` first to see the cost;
~430 credits Topaz / ~25 Recraft). Check `covers/report.json`: every cover has a `covers/<sha1>.webp` and an entry, flagged
items have a decision (rejected → the original as WebP), credits before/after recorded for the report. Never print the key.

### 2. Throwaway copy of prod

- Dump prod read-only over SSH (no writes on prod):
  `ssh -i ~/.ssh/id_ed25519 root@46.8.221.127 'D=$(docker ps -q -f name=inex-glass-prod-db-znnpts); docker exec $D sh -c "pg_dump -U \$POSTGRES_USER -d \$POSTGRES_DB -Fc"' > <scratch>/prod.dump`
  (SSH to this host works only when the user's Xray routes 46.8.221.127 direct — it does now.)
- Local Postgres: docker container `inex-glass-postgres-1` (start Docker Desktop / `docker start inex-glass-postgres-1`;
  user `dev_user`; local PG 18 = prod). Create DB `inex_glass_prodcopy_test` and `pg_restore --no-owner --role=dev_user`
  into it. Postgres needs `max_locks_per_transaction=256` (set in docker-compose).
- Never touch the regular dev DB `inex_glass`. **Environment switching:** `pnpm audit:content` is a `payload run`, and
  `next build` / `next start` read `.env`; none of them accepts `--env-file`. So set the overrides in the SHELL environment
  for those commands (a variable already present in the process env wins over `.env`):
  `DATABASE_URL=<copy>`, `SITE_URL=http://localhost:3100`, `MEDIA_DIR=<scratch>/media` (a separate scratch media dir for the
  prod copy — do not mix with the dev media). `tsx --env-file=<tmp env>` is fine for the loader only. The tmp env / exports
  contain secrets: keep them out of git and delete afterwards.
- Pre-existing prod images referenced by the copy are not on the local disk (prod media files are not downloaded), so they
  show as broken images in the screenshots — only the imported objects are judged.
- Back up the dev `scripts/.import-tmp/media-index.json` first, or avoid the problem: run the loader with
  `--out=<scratch>/out` so the dev index and `slugs-objects.json` are untouched.
- Clear `.next/cache/fetch-cache` when switching DBs.

edit `data/content/*.json` now — tasks 04/05 are done) and re-run. Revert `src/payload-types.ts` if regenerated.

### 5. Run the site and screenshot

Prod build on the copy: `pnpm build` (only one build at a time; env exported as in step 2) then
`SITE_URL=http://localhost:3100 NODE_ENV=production npx next start -p 3100`. Screenshots with Playwright at 375 / 1366 /
1920 (save to `scripts/acceptance/out/portfolio-objects/`):
- `/obekty/` (listing, filters show the new cities/types),
- one merged object page (e.g. `/obekty/trk-rodnik/`) and one folder-only object (`/obekty/aeroport-chelyabinsk/`),
- home `/` «Объекты» marquee (featured objects instead of the placeholders `objects-fallback`; note objects already featured
  on prod, e.g. `tk-kolco`, are part of the marquee too),
- one construction hub that lists objects by product (e.g. `/steklyannye-konstrukcii/` or a railings page).
Check: covers sharp and well cropped (4:5 on the home marquee, 427:300 on cards), no broken imported images, texts read
naturally. Stop the server afterwards.

### 6. Redirects + report

`fix-csv.ts` facts (verified in the code): it reads ONLY `scripts/.import-tmp/slugs.json` (`{ oldUrl: slug }`, written by
`import.ts`; no path argument) and the source CSV `docs/inex/12-migration-inex-su.csv`; it writes
`docs/inex/12-migration-inex-su.fixed.csv` and `docs/reports/migration-disputed.md` and never edits the source CSV. Its
`--check` has `EXPECTED.objects = 168` and the R5 collision rules, so it FAILS once the merged slugs are in — do not use
`--check` for this step.
1. Back up `scripts/.import-tmp/slugs.json` (e.g. copy to `<scratch>/slugs.json.bak`; if it does not exist, start from `{}`).
2. Merge `<scratch>/out/slugs-objects.json` into it (keys are the legacy `/portfolio/...` paths; the merged object slugs win
   over the old per-page ones, e.g. `koncertnyj-zal-omsk` for the three Концертный зал pages).
3. Run `pnpm tsx --env-file=.env scripts/import-inex/fix-csv.ts` (no `--check`).
4. Diff the new `12-migration-inex-su.fixed.csv` and `migration-disputed.md` against the committed ones (`git diff`) and
   describe the redirect changes (many-to-one merges, slug differences like `koncertnyi-zal-omsk` →
   `koncertnyj-zal-omsk`) in the report. Restore the backed-up `slugs.json` afterwards.

Write `docs/reports/portfolio-objects-import.md`: summary numbers, per-object table (slug, city, type, photos, cover model,
featured), «уточнить» list per object, skipped objects (e.g. `tk-kolco` published manually — what the import would add),
kie.ai credits spent, the redirect diff, and the prod run checklist from `specs/portfolio-objects-import/action-required.md`.
