# Requirements: редизайн админки Inex Glass и уведомления MAX

## Summary

Сайт inexglass.ru (Next.js 16.4 + Payload 3.91, Postgres `idType: 'uuid'`) полностью реализован по `specs/inex-glass-site/`. Заказчику не понравилась стандартная админка Payload: внешний вид, навигация, нет дашборда, неудобно обрабатывать заявки. Ему нравятся «самописные» админки из наших других проектов (lotwork — дашборд, remonttv-74 — канбан заявок).

Решение: перекрасить и доработать админку **внутри Payload**, не заменяя её. Согласован HTML-макет из 4 экранов (`res/admin-mockup/`): дашборд, канбан заявок, карточка заявки, редактирование страницы. Дополнительно — уведомления о заявках и заказах в российский мессенджер MAX (бот у заказчика есть).

Ожидаемый результат: менеджеры работают с заявками в канбане и карточке, видят на дашборде, что требует внимания, получают уведомления в MAX; админ редактирует страницы в той же теме. Права, версии, Lexical, хуки и вся существующая логика заявок/заказов продолжают работать.

## Goals

- Тема админки по макету: navy-меню `#324B64`, Rubik, токены сайта (`--ig-*`), только светлая тема, адаптив 375 / 1366 / 1920.
- Своё боковое меню: группы «Работа» (Дашборд, Заявки, Заказы, Отчёты), «Сайт» (Страницы, Статьи, Объекты, Медиатека), «Каталог и цены», «Система»; счётчики новых заявок и заказов в работе; видимость по правам (менеджер видит «Сайт» и «Каталог и цены» для чтения).
- Дашборд: «Требует внимания», «Пульс» с периодом и сравнением, воронка (с разбивкой отказов по причинам), источники, заказы по статусам, последние заявки.
- Канбан заявок: колонки из справочника `lead-statuses`, перетаскивание (мышь, тач, клавиатура), диалог отказа (код причины + текст), подтверждение перевода в «Договор» (создаёт заказ), «Взять себе», фильтры как в текущем списке, переключатель «Канбан / Таблица», мобильный режим (вкладки колонок + «Перенести в…»).
- Карточка заявки (вкладка «Сводка»): контакты, «Что нужно клиенту», файлы, атрибуция, панель «Обработка» (статус, ответственный, назначить себя, флаги, код причины отказа, сумма КП), повторные обращения, согласие ПДн, комментарии и история (статусы, назначения, уведомления).
- Форма страницы: счётчики SEO 70 / 170, превью сниппета, «Изменена / Кем», превью черновика.
- MAX: новая заявка → групповой чат; назначение и смена статуса → личка ответственного (и группа для статусов по настройке); события заказов; напоминание «новая без ответственного > 2 ч» (раз в 15 мин, один раз на заявку). Привязка лички — кнопка «Подключить MAX» (deep link), группы — одноразовый код. Переключатели событий в настройках сайта.
- Новые поля: код причины отказа, сумма КП, `updatedBy` (заявки, страницы), поля MAX, коллекция `notification-log`.

## Non-Goals

- Отдельная админка вне Payload (`/panel` на shadcn) и замена Payload.
- Замена Lexical на Markdown + шорткоды.
- Telegram и другие мессенджеры.
- Callback-кнопки MAX («Беру в работу» из чата) — только link-кнопки «Открыть заявку».
- Новые роли и изменение прав доступа к коллекциям (кроме доступа к новым полям).
- Тёмная тема админки.
- Изменения публичного сайта, кроме чтения черновика в режиме превью (task-11).

## Acceptance Criteria

- [ ] Все 4 экрана макета реализованы; скриншоты 375 / 1366 / 1920 визуально соответствуют `res/admin-mockup/`.
- [ ] Остальные экраны админки (списки, заказ, глобалы, логин, медиатека) в той же теме, без поломок вёрстки.
- [ ] Хуки заявок работают из канбана и карточки: валидация причины отказа, `statusChangedAt`, создание заказа при «Договоре», уведомление ответственного, версии.
- [ ] Менеджер не может удалить заявку, изменить чужой `maxUserId`, редактировать страницы/каталог; видит их для чтения.
- [ ] MAX: привязка лички и группы работает; уведомления приходят по всем 5 событиям, без дублей при ретраях; на стейджинге уходят только в тестовый чат или не уходят; при стирании ПДн сообщения MAX удаляются.
- [ ] Webhook MAX отклоняет запросы без верного секрета, ограничен по частоте.
- [ ] Миграция `admin_redesign` применяется и откатывается; `payload-types.ts` и `importMap.js` закоммичены владельцами.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e` зелёные; существующие e2e (в т. ч. `admin-leads.spec.ts`, `e2e/acceptance/admin.spec.ts`) обновлены и проходят.

## Assumptions

- Бот MAX создан и прошёл модерацию; у заказчика есть токен (партнёрская платформа → Чат-боты → Настройки).
- Для webhook есть публичный HTTPS-домен (staging/prod). Локально MAX проверяется моками.
- Node в контейнере может потребовать корневой сертификат Минцифры (`NODE_EXTRA_CA_CERTS`) для `platform-api2.max.ru`.
- Объёмы CRM небольшие (десятки заявок в день), поэтому агрегаты дашборда считаются запросами `count`/`find` без отдельных таблиц.

## Technical Constraints

- **Payload 3.91.0**, Next 16.4.2. Тема: `admin.theme: 'light'`; переменные `--theme-elevation-*`, `--theme-success|error|warning-*`, `--font-body`, `--style-radius-*`, `--nav-width`, `--theme-bg`, `--theme-text` (см. `node_modules/@payloadcms/ui/dist/scss/{app,colors}.scss`). CSS Payload лежит в `@layer payload-default`; незаслойный `custom.scss` его перекрывает.
- **Tailwind в админку не подключать** (preflight конфликтует с Payload). Стили админки — SCSS, классы `.iga-*`, по партиалу на задачу в `src/app/(payload)/styles/`. Токены — из `src/styles/ig-vars.css` (вынесенный `:root` из `ig-tokens.css`).
- Цвета только из токенов DESIGN.md (`#267D70` кнопка, `#2B8C7E` бренд, `#324B64` navy, статусы success/warning/danger/info). Оранжевый/голубой логотипа — только в логотипе. Без эмодзи и бесконечных анимаций; `prefers-reduced-motion`.
- Rubik через `next/font/local` (`src/app/(site)/fonts.ts`), в админку — `RootLayout htmlProps={{ className: rubik.variable }}`.
- Меню: `admin.components.Nav` (server) + `NavWrapper` / `NavHamburger` из `@payloadcms/next/client`. Дашборд: `admin.components.views.dashboard.Component`. Канбан: `leads.admin.components.views.kanban = { Component, path: '/kanban', exact: true }` → `/admin/collections/leads/kanban/`. Карточка: существующая вкладка «Сводка» (`/admin/collections/leads/:id/summary`, `src/payload/admin/leads/lead-summary-view.tsx`).
- Изменения заявок из UI — `fetch PATCH /api/leads/:id` (`credentials: 'same-origin'`) + `router.refresh()`, как `src/payload/admin/orders/status-panel.tsx`. Ошибки валидации приходят 400 с field errors (держится на `serverExternalPackages: ['payload']` в `next.config.ts`).
- Server components по умолчанию; `'use client'` только для интерактива; пропсы сериализуемые. Custom views сами проверяют доступ (`getRole(user)`, как `src/payload/admin/views/leads-report.tsx`).
- Схема: миграции expand-only; slug-и kebab-case; UUID. Любая новая регистрация компонента → `pnpm generate:importmap`.
- MAX Bot API: base `https://platform-api2.max.ru`; заголовок `Authorization: <token>` (без Bearer); `POST /messages?chat_id=…|user_id=…` `{ text, format: 'html', notify, attachments: [{ type: 'inline_keyboard', payload: { buttons: [[{ type: 'link', text, url }]] } }] }`; текст ≤ 4000 символов; лимиты 30 rps и 2 сообщения/с в один чат (429); `DELETE /messages?message_id=…`; webhook `POST /subscriptions { url, update_types, secret }` → заголовок `X-Max-Bot-Api-Secret`; события `bot_started` (`payload` из `?start=`, ≤128 символов), `bot_added`, `bot_removed`, `bot_stopped`, `message_created`; 401/403/404 — перманентные, 429/5xx — ретраи. Plain `fetch`, без SDK. OpenAPI: `res/max-api/schema.yaml`.
- Язык UI и контента — русский; код и идентификаторы — английский.
